# Repair a shipped NAPI-RS WASI loader from the module beside it

A NAPI-RS package that ships its WASI build carries two generated files: the
module `<binaryName>.wasm32-wasi.wasm` and the loader `<binaryName>.wasi.cjs`.
The loader calls each `__napi_register__<name>_<sequence>` function the module
exports before it initializes the module; a function it does not call
registers nothing, and the export it would have registered is missing. ADR-0028
leaves such a package alone, because its loader is what the package's own code
tries first.

nx 22.6 to 23.2.1 publish a loader generated by another build than their
module. The loader of 23.2.0 names 53 register functions; the module exports
40, and one of them under a name the loader uses. Every nx command then fails
on a missing export (`isAiAgent is not a function`, `WorkspaceContext is not a
constructor`) wherever the WASI build runs, Node with `NAPI_RS_FORCE_WASI=1`
included. Here the WASI build is the only one, so nx does not start at all.

## Decision

**After an install, the Command Proxies rewrite a shipped WASI loader whose
register calls are not the register functions its module exports.**

- **Which loaders.** Every installed package with `napi` metadata is searched,
  to four directories deep and outside `node_modules`, for
  `<napi.binaryName or index>.wasi.cjs`. nx keeps it in `dist/src/native`.
- **Against which module.** The one the loader loads: the
  `.wasm32-wasi.debug.wasm` beside it when the package ships one, otherwise
  `.wasm32-wasi.wasm`. Its export section is read without compiling it.
- **The rewrite.** The body of `__napi_rs_initialize_modules` becomes the
  module's register functions in the order of their sequence numbers, and the
  loader ends by copying what the module registered onto `module.exports`; the
  named exports the stale loader lists stay before it. A loader that already
  matches its module is left byte for byte, so the step is idempotent and does
  nothing for packages built from one build.
- **No map entry, no version range.** The repair is derived from the files the
  package itself ships, like the companions of ADR-0028.

## Consequences

- `nx --version`, `nx show projects` and `nx sync` run after `npm install`
  without any change to the project.
- An install reads the module of every NAPI-RS package that ships a WASI
  loader, nx's being 4 MB to 5.6 MB.
- A package whose loader shape differs (another initializer name) is not
  recognised and is left as published.
